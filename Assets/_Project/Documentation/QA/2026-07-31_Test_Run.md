### Root cause

The post-BOOT mission system links missions by objective category. Terminal missions were searching for the previous mission of the same category across the entire catalog, so a pre-Terminal combat mission could incorrectly remain their prerequisite. The Terminal phase also had no explicit final-choice gate.

### Fix and focused verification

- Every `TERMINAL PROTOCOL` mission now requires `break_final_choice` to be complete.
- Category chains restart inside the Terminal phase instead of inheriting pre-Terminal prerequisites.
- A pre-Terminal category completion can no longer announce a still-locked Terminal mission.
- Completing final choice reports `terminal_1000_kills_run` as the new directive.
- Regression coverage checks both first Terminal category heads and verifies later Terminal missions remain locked.
